Security Notes & Testing Guide

Diese Demo verwendet echte Browser-Kryptografie, bleibt aber bewusst eine lokale SPA-Demo.

Hashing

Passwortfluss: Salt (16 Bytes) → SHA-256 → SHA-512. Nur der finale Hash wird gespeichert.

AES-256

Sichere Notizen werden mit AES-256-GCM verschlüsselt und erst nach Passwortprüfung entschlüsselt.

XSS / CSRF

Benutzernamen werden strikt validiert, UI schreibt per textContent, state-changing Aktionen prüfen einen Session-Token.

  • Manueller Test: Admin registrieren → ausloggen → fünfmal falsches Passwort → Sperrlog prüfen.
  • Node-Tests: node --test auth.test.mjs
  • Bestehende Python-Tests: python test_tokenizers.py
  • OAuth2 Demo-Test: GitHub/Google/Microsoft Button klicken → Callback wird simuliert → Session aktiv.
  • System Account Test: Konto anlegen, anmelden, Passwort-Stärke prüfen und Secure Note AES-256 speichern.
  • Admin Test: Audit Logs ansehen/exportieren und User-Übersicht im Admin Panel prüfen.
  • 2FA-Hinweis: Ohne Backend wird hier nur ein Upgrade-Hinweis angezeigt, keine echte zweite Faktor-Verifikation.
